# See-Through 本地部署与优化

## 何时使用

本地 See-Through 是最后可选项，不是默认路线。原画确认后优先让用户在 ModelScope 网页自行上传并下载 PSD；用户选择 Agent 代传时才走在线 API。只有在线入口不可用、用户仍要继续并明确选择本地运行时，才安装或启动本地项目。用户带回 PSD 后在本机复核不等于本地部署。

当前 Windows 工作机上的项目目录是 `E:\Code\see-through-webui`。不要为了让这个项目运行而在其它目录再复制一份 See-Through，也不要未经检查就重复安装 CUDA、Python、PyTorch 或模型。开始前先检查 `nvidia-smi`、`where.exe python`、现有虚拟环境和 C、D、E 盘的 CUDA/PyTorch/模型缓存；兼容的现有组件继续使用，确实缺失的依赖才补装。Python、pip 缓存和可复用工具优先放在 `D:\Tools`，项目、虚拟环境、模型缓存和输出保留在 D 或 E 盘，不主动占用 C 盘。下载失败时改用可用镜像源并保留安装日志，不通过反复删除环境碰运气。

## 已验证门槛与启动

本地 WebUI 面向 Windows 10/11、NVIDIA RTX 20 系及以上显卡；8GB 显存、8GB 内存和约 20GB 可用磁盘是最低实用门槛，首次下载约 6GB。RTX 2080 Super 8GB 可以运行，但 1024 推理接近显存上限，进入共享显存后会显著变慢。

在项目目录中先验证现有环境，而不是直接重装：

```powershell
nvidia-smi
& E:\Code\see-through-webui\venv\Scripts\python.exe -c "import torch; print(torch.__version__, torch.version.cuda, torch.cuda.is_available(), torch.cuda.get_device_name(0))"
```

缺少项目环境时才运行 `install.bat`，成功后用 `run.bat` 启动，在浏览器打开它报告的本机地址。安装、启动和一次推理都要检查退出码与日志；声称安装成功前必须用一张已经打开确认过的正常日系二次元单人图跑通 PSD 输出，并按主 Skill 路由的分层复核流程生成重组对照和视觉结论。测试图不能用抽象测试卡，也不能用正式用户原画之外的文件冒充正式结果。

## 分辨率与显存

当前 WebUI 接受 512 到 2048，自动取最近的 64 倍数，因此 704 可以运行；最低值是 512。512、704 或 768 只适合连通性与快速预检，不能靠后期高清放大修复已经拆错的语义。正式原画默认 LayerDiff 使用 1024；深度阶段默认 720/768 即可。出现显存不足时先降低预检分辨率或恢复正确的 offload，不自动牺牲正式结果，也不把共享显存导致的极慢误判为程序卡死。

## 当前本地版本的已知问题

`E:\Code\see-through-webui` 是可恢复的本地工作副本，已有针对这台机器的修改，不能把它与官方在线服务混为一谈。继续优化前先查看 Git diff 和实际日志，保护已经存在的改动。

- WebUI 当前固定传入 `--no_group_offload`。这会让 8GB 显卡更容易超过物理显存；应恢复可选的 group offload，并在同一图片、同一 seed 下比较 NF4 与官方 BF16 block-swap 路径。
- 当前 Marigold 为每个图层重复运行“一层加全图”的双图推理。它能降低单次显存，但约二十个图层会重复二十次，且各次深度缺少统一批次校准，是耗时过长和排序不稳定的来源。
- 当前 Alpha 总和先被裁剪到 0～255，随后却检查是否大于 256；这个条件永远不会成立，会影响前后发、眉毛、眼睛和服装等重叠区域的深度判断。
- See-Through 按单个动漫人物和固定身体语义槽工作。人物旁边的鹿、第二个完整角色或大型伴生物容易串入头发、服装、翅膀或配饰层；正式输入默认单主体，第二主体应独立处理。

## 后续优化顺序

先修推理链路，再考虑模型训练：

1. 修正 Alpha 遮挡条件，并为重叠层增加可复现测试。
2. 恢复 8GB 显存可用的 group offload，固定输入与 seed 对 NF4、BF16 block-swap 做视觉和耗时对照。
3. 把 Marigold 改为每批 4～6 层，并让每批共享同一张全图深度作统一校准；跳过完全透明的空层。
4. 把流程拆为语义拆层、预览确认、深度排序和 PSD 四阶段。拆层已经缺眼、串入第二主体或主要部件错误时立即停止，不继续浪费时间跑深度。
5. 接入项目已有的 AnimeInstanceSegmentation 或 SAM2 入口，让用户或 Agent 先选定主人物；只有主实例进入 LayerDiff，第二主体另行处理。
6. 增加人物掩码越界、异常连通区域、语义层缺失、图层顺序矛盾和重组误差检查，并始终保留原图、PSD、预览、日志和同参数对照。

不建议在这台机器上重新训练 LayerDiff。完整训练需要远超单张 8GB 消费显卡的算力；本地工作的重点是稳定推理、提前止损、统一深度和视觉验收。任何优化都先用测试素材确认，再处理用户原画；结果仍须由外部 Agent 实际看图，不能用运行成功或指标变小代替分层正确。
