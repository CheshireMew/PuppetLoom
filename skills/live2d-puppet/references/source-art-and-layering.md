# 原图生成与 See-Through 分层

## 职责和输入路由

本流程只负责把角色需求变成 PuppetLoom 可检查的输入。外部 Agent 理解设定、检查画面并调用图像工具或服务；See-Through 生成候选分层 PSD；PuppetLoom 从 PSD 确定性分析和制作。不要把单张 PNG 称为已经完成的 Live2D 形象，也不要把生图模型、提示词引擎或 Agent 运行时加入 PuppetLoom。

按实际输入选择唯一路线：

1. 同时有原图和 PSD：保留两者，先做本地重组一致性检查和 `inspect`；只有用户明确要求继续制作角色且视觉验收成立，才进入 `create`。
2. 只有 PSD：可以 `inspect/create`，但明确报告没有原图参考，不能声称已经验证分层前后完全一致。
3. 只有原图：先展示并确认这张图适合正式拆分，再列出三种路线让用户选择：推荐用户在指定 ModelScope 网页以 1024 自行上传、下载 PSD；偷懒选项是由 Agent 自动上传这张已确认原图并下载结果；在线入口不可用时才推荐本地部署。用户选择 Agent 代传就构成本次具体上传授权，不再重复确认，没有选择则不上传。
4. 完全没有原图：若环境具备图像生成能力，生成一张正常日系二次元可绑定原图并实际打开检查。用户给定角色设定时保持该设定。生成后展示原图并停止，等待用户确认；确认后列出上一条的三种分层路线。若无法调用生图工具，则原样交付下面的一条当前任务指令和 ModelScope 网址，等待用户带回原图或 PSD。

本地部署只作为在线入口不可用、用户仍要继续并明确选择本地运行后的最后可选项；普通路线不自动安装、启动或优化本地 See-Through。真正进入本地路线前按主 Skill 路由读取本地部署参考。下文的 `-ReviewPsd` 只是本地检查用户带回的 PSD，不进行 See-Through 推理。

用户说“只使用现有素材”时，不生图、不上传、不下载新 PSD，只报告当前素材缺口。

用户只要求生成或测试 PSD 时，这是一个完整且独立的任务边界：交付原图、PSD、重组与视觉结论后停止。不要创建 PuppetLoom 项目，不要生成 `rig-spec`，也不要调用 `create`、`agent plan` 或 `agent apply`。

## 可绑定角色原图

正式制作优先使用高分辨率单人半身或全身图；半身图只能制作素材实际覆盖的范围。头部基本端正、脸部基本对称、双眼自然睁开、闭口中立，前发、后发、眉毛、睫毛、脸、颈部、四肢、衣摆和点名配饰边界清楚。人物可以有轻微动态和张力，不必完全正面呆站，但关键部位不能因交叉手臂、道具、强透视或大面积重叠而无法判断。人体比例服从用户设定和参考，不限定头身比，也不能为了方便拆层擅自改成矮小、幼态或 Q 版。

“适合 See-Through 拆分”只要求主体、轮廓和关键部件在完整画面中可辨，不等于简化角色设计。不能为了方便拆层主动减少服装层次、装饰和画面完成度，也不能把角色改成幼态、Q 版或僵硬站姿。正式原画与压力测试分开：压力测试可以加入复杂姿态、手持道具或伴生角色来观察模型极限；正式分层仍以一个人物为主体。第二个完整角色或大型伴生物容易被混进人物的头发、服装、翅膀或配件层，默认应作为独立素材处理，不能把压力测试通过等同于正式素材合格。

本项目生成新的日系二次元角色原画时，默认不把完整鲸鱼娘原画交给图像模型。长期使用的正向画风文字是：“清爽可爱的日系二次元立绘；线条干净连续，色块清楚稳定，使用少量边界明确的赛璐璐阴影；头发、衣物与配饰都由轮廓、连接和前后关系清楚的实体结构组成。严格禁止虚假纹理和虚假装饰。”这段文字直接并入唯一的当前任务指令，不另建风格合同。只有用户明确要求使用鲸鱼娘整图作参考时，才把 `assets/blue-whale-maid-reference/blue-whale-maid-source-art.png` 交给图像模型，并明确它只负责画风，不负责新角色的身份、服装或物种特征。`blue-whale-maid-layered.psd`、转头图和三张表情图只供分层、绑定和补表情时查看，不进入原画生图上下文，也不能当作可直接导入的透明表情素材。

没有原图时，先从本次任务最早一轮重新核对当前有效材料：人物身份、角色设计、画风和待编辑候选各自只能承担明确职责。后加入的材料默认是补充，后来的单项纠正也默认只增加或修正点名内容；只有用户明确说“不要”“放弃”“改用”“只用”或同等意思时，才退出此前材料或要求。这个核对只用于形成输入，不作为第二份提示词交给图像模型。

实际交给图像模型的内容始终只有一条当前任务指令。用户已经给出完整提示词时原样交接；否则只写用户目标、每份参考材料负责什么、单人半身或全身等必要输出形式、平台固定要求和用户明确提出的硬要求。用户没有规定的服装、翅膀、配色、装饰和构图细节继续交给图像模型决定；不要附加长篇负面清单、评分标准、验收说明或第二套提示词。耳朵等结构要求直接写成当前角色必须成立的关系，例如“鹿耳是唯一的一对耳朵，取代正常人耳”，但不把当前角色的器官、服装和配饰要求固化为其它角色的默认。用户询问实际使用了哪些图片或提示词时，逐项返回真正进入本次调用的图片及职责，并逐字返回实际提示词，不能用计划、概述或事后改写代替。

用户明确不允许把真人照片交给图像模型时，不上传照片；只提取适合二次元表达的脸部轮廓、眼形与间距、眉形、五官位置和整体神态，省略皮肤纹理、妆容、写实嘴唇厚度和其它会把画风推向照片质感的微观特征。用户允许使用照片时，照片仍只承担人物身份职责，不能顺带决定服装、物种或画风。

如果候选的身份、角色设计或整体方向已经错误，回到仍然有效的原始参考完全重新生成，所有已经被否定的生成图都退出图片输入，不能在错误候选上层层编辑。只有用户明确说“改这张”“保留这版”或同等意思，或者问题确实只是局部细节时，才把用户指定候选作为图片输入，并只修改点名内容；未点名的设计、姿势、构图和画风保持不变。

生成后实际打开完整原图和需要放大的关键区域，检查人物身份、角色设计、用户硬要求、唯一耳朵等解剖关系、线条与色块是否清楚、衣物和配饰的连接及前后关系是否成立，以及关键部位遮挡、裁切和背景混合。随机纹理、没有连接关系的装饰、重复器官和严重粘连都属于原图阶段的问题，不能期待 See-Through 或后期修层补救。Agent 可以报告客观可见问题，但用户对角色是否可爱、好看和方向是否正确拥有最终判断；每次只中性展示当前候选并等待反馈，不因自评失败就在同一轮自动连续生成。即使 Agent 认为画面可用，也不自行上传。是否重新生成仍由用户决定。不使用高饱和绿幕作为正式 See-Through 输入。

## See-Through 分层

默认网页入口是 [ModelScope See-Through](https://modelscope.cn/studios/ljsabc/See-Through/?st=1WIdxVcPQ8ylM43-0Vr14FQ)。原画确认后直接列出以下三个选择，不替用户暗中决定：

1. **推荐：自己上传。** 打开上述网页，分辨率选择 1024，上传已确认原画，下载 PSD，最好同时下载图层预览，再把原画和 PSD 一起交回。
2. **Agent 代传。** 用户选择这一项即授权 Agent 只上传当前已确认原画并下载本次结果；不得扩大到其它文件或以后任务。
3. **本地部署。** 仅当在线网站不可用时推荐；用户选择后按主 Skill 路由的本地部署流程检查和运行 `E:\Code\see-through-webui`。

在用户选择前停止，不上传、不安装，也不把本地部署冒充默认路线。

用户带回原图和 PSD 后直接进入下面的本地复核，不再上传任何文件。用户选择“Agent 代传”后，调用 ModelScope 的独立 Gradio 服务 `https://ljsabc-see-through.ms.show`；其命名 API 端点为 `/inference`，接收图片、`resolution`、`seed` 和 `tblr_split`，返回分层 PSD 与图层预览。自动路线默认分辨率同样是 1024，不自动提高到 1600。

获准自动上传后通过包装脚本调用，不控制 Windows 鼠标：

```powershell
& <skill>\scripts\acquire_layered_psd.ps1 E:\Input\character.png -Resolution 1024 -Seed 42 -SplitLimbs
```

自动路线的结果写入 Skill 自有且被忽略的 `runtime/see-through/<UTC 时间-随机编号>/`，不覆盖既有任务。即使接口与 `inspect` 均成功，结果仍保持 `readyForCreate: false`，因为脚本只证明服务返回了 PuppetLoom 可读取的 PSD 和待审查证据，不证明分层语义或重组画面正确。获准自动上传后先用只读检查确认当前 API 协议仍匹配：

```powershell
& <skill>\scripts\acquire_layered_psd.ps1 -Check
```

每个运行目录自带 `source-original.*`、`source-upload.png`、`source-normalized.png`、PSD、带语义名称的 `previews/`、`previews/index.json` 与 `previews/contact-sheet.png`、`inspect.json`、从实际可见图层生成的 `recomposition.png`、`difference.png`、`comparison.png`、`comparison-metrics.json`、待 Agent 填写的 `visual-review.json` 和完整调用记录。预览总览用于一次检查全部语义层，再对缺眼、长条污染或异常边缘的单层预览放大确认。`source-original.*` 是未经改写的输入副本；`source-upload.png` 是 EXIF 校正、不缩放、白底不透明副本，在线获取时它是实际发送给 See-Through 的文件，本地复核时只用作同规则比较而不会上传；原图已有透明像素时不会被静默覆盖。`source-normalized.png` 才是用于同画布比较的居中补方与缩放结果。三者路径和哈希都进入调用记录，返回结果时明确指出原图、实际上传图和 PSD 在哪里。

只有传输超时、连接中断或事件流没有完整结果时，脚本才使用同一分辨率、种子和拆肢选项自动重试一次，并在 `attempts/attempt-1`、`attempts/attempt-2` 中分别保留记录。画面缺眼、残留底色或分层错误不是传输故障，不能自动批量换种子；Agent 看过证据后再决定是否另开一次调用。

已有原图和 PSD 时使用本地复核，不上传任何文件：

```powershell
& <skill>\scripts\acquire_layered_psd.ps1 E:\Input\character.png -ReviewPsd E:\Input\character.psd -OutputRoot E:\Output\layering-review
```

获准的自动路线若失败、持续排队、结果 URL 无法下载或服务协议改变，保留错误任务目录并报告失败；不要假装已经获得 PSD，也不要自动改分辨率、换种子或改用浏览器继续上传。回到三个选择：用户可在准确的 ModelScope 网页以 1024 手动处理，或在线入口不可用时明确选择本地部署。

See-Through 返回的单层采用原画画布坐标和透明通道。复核、补层或迁移时必须保留全画布尺寸、图层原始位置和解剖学左右；不能把裁出的局部部件任意缩放、镜像或凭目测重新摆放。完整角色制作中缺少左右闭眼、微张嘴或张口时，Agent 默认按原画、PSD 重组图和对应局部参考生成真正缺少的表情素材，不需要再次索取授权；已有闭嘴绝不重画。图像生成不能作为默认的 PSD 主要语义修复器：不要把孤立后发、翅膀、腿或其它主要结构生成为绿幕图，再用色键和代码拼回 PSD。这样得到的坐标、朝向、透明边和画风没有可靠保证。

### 多份 PSD 的部件整理

用户提供多份 See-Through PSD 并要求结合原画整理时，原画是形状、颜色和前后关系的语义真源，各 PSD 只是 donor 候选。先建立逐部件来源清单，至少记录候选图层、完整轮廓、被遮挡区域的补底、透明边质量、内部不透明度、是否与其它语义粘连、画布位置和应处的前后顺序，再选择基础 PSD 与每个替换部件。不能因为某份 PSD 分辨率更高、图层更多或整体重组更接近原画，就默认它的每个部件都更好；头饰、发梢、角、耳、手指、鞋尖和画布边缘附近的结构必须单独放大检查。

配方先选定一个规范画布，所有坐标和矩形都以它为准。donor 与规范画布相同才可直接复制；不同分辨率时默认拒绝，只有确认两者是同一整画布构图、宽高比一致并在配方中明确使用 `fit-full-canvas`，才允许 Photoshop 在不保存 donor 的前提下整画布等比例适配。宽高比不同、局部裁切、姿势或构图不一致时停止，不拉伸，也不裁下部件后凭目测摆放。

所有候选都缺少、但原画清楚存在的结构，可以从原画用 Photoshop 的连续背景选择或主体选择恢复到规范画布。选择产生的是边界蒙版，不能把 RGB 亮度、灰度或“越白越透明”直接映射为 Alpha；白色、浅金色和其它浅色实体内部仍应保持不透明，只有抗锯齿边缘可以自然过渡。补件后同时查看彩色逐层细节图与 Alpha 灰度图，确认没有截断、实心浅色被掏空、白底变成不透明块或边缘被去白过度。

最终 PSD 必须逐层单独检查，再检查完整重组。每个交付图层都要在高分辨率细节图中确认轮廓和内容，在 Alpha 图中确认透明结构，并对照原画判断是否完整；触碰画布四边或在缩略总览中尺寸很小的图层优先放大。PSD 能重新打开、画布尺寸正确、图层数量充足或整图看起来接近原画，都不能代替这项逐层检查。

## 下载后的验收

脚本验证文件非空且以 PSD 签名 `8BPS` 开头。随后运行：

```powershell
& <skill>\scripts\invoke_puppetloom.ps1 inspect --input E:\Output\character.psd --json
```

实际打开 `source-normalized.png`、`recomposition.png`、`comparison.png`、`previews/contact-sheet.png` 和需要放大的单层预览，确认脸、双眼、虹膜/睫毛、前发、后发、脖子和上身等核心语义存在；全身角色还要检查手臂、腿、裙摆、尾巴和配饰。`recomposition.png` 必须由 PSD 的实际可见图层强制合成，不能信任 PSD 内置预览图。对照图同时展示白底、深色底和只保留角色有效 Alpha 的放大差异，用于检查脸形、五官、发际线、服装图案、肢体轮廓、透明边、残留底色、离散噪点和画布位置。

透明 PNG/WebP 的裸查看器可能显示 Alpha 为零区域里的无效 RGB；只有在未增强的白底、深色底、目标显示尺寸或实际运动画面中仍可见的条纹、底色和噪点，才能证明它们影响最终画面。对 Alpha 做倍率放大、阈值着色或框选时，必须在图上和说明中写明增强规则，并同时给出未增强画面；增强诊断只用于定位像素，不能单独证明污染对用户可见或构成阻断，也不能按诊断区域的外接矩形面积判断污染严重程度。若异常只在增强后可见，先把它记录为待判断或可清理噪点，再根据实际合成影响分级。

判断异常来自原图还是 See-Through 拆分时，要同时比较 `source-original.*` 的真实 RGB/Alpha、`source-normalized.png`、PSD 单层 Alpha 和 `recomposition.png`。原图没有 Alpha 只能证明原图不存在隐藏透明蒙版，不能单独证明其可见 RGB 中没有相似痕迹；归因仍以原图画面和拆分结果的对应差异为准。

`inspect` 通过、图层数量充足或 `comparison-metrics.json` 的差异较小，都不能自动接受候选。外部 Agent 必须把 `visual-review.json` 中五官、头发、服装肢体、`layer-order-and-occlusion`、背景透明边和整体重组逐项记录为通过、可后修或失败，并给出 `blockingIssues` 与 `repairPlan`。图层顺序按从后到前检查，至少确认后裙在裸露腿后、腿在前裙后，后发在脖子和脸后，眉毛在脸前且不会因眨眼消失；前发仍可在脸和眉眼前。实际设计不同可以调整，但必须以原画重组为证据，不能只按角色名猜。

如果错误只是几个完整独立图层的前后顺序，候选可标为 `accepted-with-repairs`，`repairPlan` 逐条记录要移动的 layer ID、相对目标和视觉原因；进入项目后由 Agent 通过可恢复的 `move-layer` authoring 操作调整，再查看 neutral、眨眼和身体动作证据。

背景残片、低透明托底和硬矩形托底先判断“是否能客观圈定”，不能只看矩形外接框。与主体断开、删除后不改变有效轮廓、阴影、抗锯齿和隐藏运动延展的独立杂质可以进入修复；整层纯杂质用 `delete-layer`，同层中边界明确且完全不含角色内容的区域才用 `clear-region`。需要保留原层语义时，也可以用保持原画布和原坐标的清洁层通过 `duplicate-layer/delete-layer/rename-layer` 整层替换，但不能裁切、缩放或目测重摆；白边或边缘污染只有证据明确时才用 `remove-white-matte` 或 `defringe`。需要交付修复后的 PSD 或异常超过普通创建的微小低 Alpha 清理边界时，必须运行 `psd repair` 或 `psd review`，查看新 PSD 的白底、深色底、棋盘格、逐层总览和原图对照，再用 `psd finalize` 绑定结论；所有输出写到新路径，原 PSD、输入哈希、全画布尺寸和图层位置都保留。普通 `create` 的保守导入清理只能让项目忽略少量噪点，不能被表述为 PSD 已经修好。

若异常与真实轮廓相连，矩形区域包含被遮挡结构、补底或动作时需要显露的像素，清理规则需要猜角色内容，或未增强的合成与运动画面已经出现大面积白雾、底色、绿边和硬截断，就不能用阈值或整块清除掩盖，应标为 `rejected`。若前后裙、前后发、眉毛与脸或其它前后结构已经粘在同一图层，无法只靠移动完整图层修复，同样标为 `rejected`。缺失核心五官或主要身体区域、第二主体串层、画布严重错位或分层结构不足以可靠创建项目时也拒绝；缺少呆毛、小配饰、少量边缘残留、孤立噪点和轻微颜色变化等不改变主要轮廓与遮挡的问题才可后修。写完结论后通过确定性入口校验三档状态并同步结果，Agent 不再手工维护两份状态：

```powershell
& <skill>\scripts\acquire_layered_psd.ps1 -FinalizeReview E:\Output\layering-review\<run>\visual-review.json
```

`accepted` 不得带阻断项或待修计划；`accepted-with-repairs` 必须有具体 `repairPlan`，但不带阻断项；`rejected` 必须说明至少一个真正阻止继续创建的 `blockingIssues`。命令校验原图与 PSD 哈希、审图证据路径和结论内部一致性，再同步更新 `visual-review.json` 与 `result.json`。用户只要求 PSD 时，返回文件、分级结论和修复计划后停止。用户同时要求继续制作时，`accepted` 可直接进入 `create --reference <原图>`；`accepted-with-repairs` 只有在问题不改变主要语义、轮廓和遮挡结构，且用户明确接受携带这些问题继续时才可进入创建，修复完成前不能把它报告为成品。`rejected` 不进入绑定，也不自动转入生图补部件、绿幕抠图或代码拼接；回到最后接受的原画或 PSD，由用户选择重新使用官方网页分层、调整整张原画或交给画师修层。
