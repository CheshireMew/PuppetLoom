# PSD2Live 导出接入与故障复核（2026-09-09）

已接入 PSD2Live 使用的 Umamo 编码器，`cubism export` 和桌面导出中心输出真实 CMO3、MOC3 与配套文件。此前“只有 Editor 才能生成 MOC3”的结论不成立。

## 这次图像错位的实际原因

最初把零散图层 PNG 直接作为 Cubism 图集，并且额外翻转了 V 坐标。第一次错误造成每个图层上下颠倒；纠正 V 后，编辑器仍对非二次幂小纹理采用了不同的尺寸归一化，结果眼睛变小、嘴鼻消失、脸与脖子脱节。

证据来自同一文件的两条路径：PuppetLoom 直接生成的 MOC3 与源项目顶点相符；把 CMO3 在官方 Editor 另存并重新导出后，顶点位置仍基本相同，但 UV 发生明显变化，PNG 尺寸没有同步变化。例：嘴部纹理为 25×9，面部为 198×185。按 PSD2Live 的 `AtlasPacker.kt` 将原像素放入有间隔的二次幂图集后，Editor 的正常脸形、眼睛、嘴巴和头颈连接恢复。仅比较两次模型读取成功无法发现这个问题。

图集修正解决了大范围错位，但官方重新导出仍暴露刘海 UV 最大约 0.001342 的偏差（2048 图集上约 2.75 像素）。这是第二个独立问题：将变形后的默认姿态当作原画网格，编码器用仿射关系拟合贴图位置时不能表达刘海的非线性造型。最终按图层原始范围与 UV 写入原画网格，将默认造型和所有动作保持在绝对关键形中；官方重新导出的最大 UV 偏差下降到约 0.000000207。不能将这项小偏差与此前非二次幂图集造成的脸部大范围错位混为一个原因。

## 采用的完整路径

1. 从有效 revision 求值实际网格、透明度、图层顺序和遮罩；采样绑定端点与组合姿态，并检查中间插值。
2. 按 PSD2Live 的确定性分行算法，保留原图尺寸、间隔和二次幂页面，统一重映射 UV；禁止零散小图直接作为页面。
3. 构建 Umamo PuppetModel，调用 `Moc3Sidecars.bundle` 与 `Cmo3Conversion.freshCmo3`，注入可编辑物理并写出 CMO3。当前模型没有父级变形器，网格已在画布空间；因此参考项目的父级坐标还原和 Bezier 编辑分割设置不需要照抄为空操作。
4. 重新读取两种格式，拒绝除已披露原画重建提示外的内容丢失；合并当前项目动作、表情、物理和显示信息。
5. 使用本机官方 Core 检查端点与组合姿态，并使用真正导出图集绘制对照；在目标 Editor 打开、检查和另存，再由官方编辑器重新导出，重复相同的对照。

参数单位扩大 100 倍，避免官方 Core 在密集关键点附近的绝对 0.001 吸附误差；侧车同步转换。Editor 不接受参数和图层 ID 中的连字符，因此使用稳定合法 ID 并记录与源 ID 的对应表；参数树也显式写入，避免 Editor 自动恢复遗漏的分组引用。不同人物的参数影响范围分别求值，没有把猫耳角色的具体参数填进通用导出器。

## 工程版本与运行时版本

上游新建 CMO3 的结构固定为 5.4，即使运行时目标选择 5.0，也不会自动变成 5.0 编辑器工程。PuppetLoom 分别提供工程 5.3/5.4 与运行时 4.2/5.0/5.3 选择。5.3 格式按照官方 Editor 5.3.01 另存结果核对：CModelSource 类版本 16 改为 15，移除 5.4 的空状态集和默认图集布局锁及对应声明；有实际新功能时拒绝转换，不仅仅改文件头。
