# 架构说明

PuppetLoom 把“读懂 PSD、生成安全项目”和“实时绘制项目”分开。桌面应用与 CLI 都调用同一个核心，不各自复制创建逻辑；实时窗口只读取已经验证过的项目，不承担绑定编辑职责。

```text
PSD + 可选原图
      │
      ▼
@puppetloom/core
  导入 → 分类 → 关键点 → 网格/权重 → 13 姿态检查 → 自动收缩/降级
      │
      ├── 普通项目目录 ──→ CLI verify / enhance
      │
      └── puppetloom.json + textures
                         │
                         ▼
               @puppetloom/renderer
                 WebGL2 + 确定性动作
                         │
                         ▼
             Electron 透明角色窗口
```

## 工作区职责

### `packages/core`

`core` 是唯一创建真源。它负责：

- 用 `ag-psd` 读取原始像素数据，遍历嵌套图层并继承分组可见性和透明度；
- 把 8、16 和 32 位像素转换到运行纹理，应用可读取的位图或矢量蒙版；
- 根据名称与透明区域分类，拆分确实跨越画布中心的成对部位；
- 推导脸部、脖子、肩部、身体和头发固定区域的关键点；
- 生成自适应规则网格、作用权重、视线裁切关系和动作上限；
- 检查 13 个姿态并依次收缩动作；仍不安全时从 `semantic` 降为 `grouped`，再降为 `minimal`；
- 写入项目、纹理、构建报告、真实姿态图和可选素材请求；
- 验证补充闭眼素材的尺寸、透明度和覆盖比例，接入前保留原项目备份。

`core` 另有 `@puppetloom/core/browser` 纯运算入口，只导出类型、数学与变形函数，避免浏览器包连带加载文件系统、PSD 解码和 Sharp。

### `packages/renderer`

`renderer` 只消费已验证项目。它为每层上传纹理和索引缓冲，每帧按统一变形函数更新顶点；虹膜使用对应眼白的安全区域裁切。普通、正片叠底、滤色、线性减淡、变暗和变亮使用 WebGL 混合状态；无法直接由固定混合管线复现的模式保留在项目中，并以普通 Alpha 合成安全显示。

`CalmMotionController` 先用种子生成观察事件，再从事件推导视线、头部、身体与头发状态。它没有每帧无关随机数，因此同一项目、同一种子和同一时间序列得到相同动作。

### `apps/cli`

CLI 是 Agent 和自动化入口。命令只调用 `core`，`play` 启动同一 Electron 透明窗口。错误在最外层统一映射为退出码，JSON 错误写到标准错误。

### `apps/desktop`

Electron 主进程拥有文件对话框、项目创建、纹理读取和角色窗口控制权；预加载脚本只暴露明确 IPC。React 创建界面不含文件系统权限。角色窗口使用相同页面的 viewer 模式，WebGL 画布保持透明，隐藏控制区在鼠标悬停时出现。

## 安全结果优先级

每次创建先按 PSD 语义完整度选择初始档位，再对预设姿态验证。动作缩放序列为 `1、0.85、0.7、0.55、0.4、0.25`。一个档位在最小范围仍出现网格翻转、严重拉伸或部件分离才会降级。`minimal` 不做脸部或肢体局部变形，只保留轻微整体呼吸、重心和倾斜，因此不依赖特定角色结构。

嘴部图层会随头部整体运动，但没有独立嘴形参数。缺少闭眼图层只会关闭眨眼并生成请求，不影响项目成功。

## 仍需真实素材验证的边界

程序化 PSD 能证明格式、分类、绑定、降级、渲染和产品链正确，但不能证明任意插画的分层质量。真实角色接入阶段仍要确认：PSD 重组与原图一致、脸部关键层完整、头发固定区合理，以及动作在具体线稿上没有视觉穿帮。这是唯一保留给新角色原图和对应 PSD 的验收阶段。
