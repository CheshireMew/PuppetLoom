# 架构说明

PuppetLoom 把“自动创建基线”“AI authoring 图”“稀疏校准”“实时绘制”和“Agent 编排”分开。桌面应用与 CLI 都调用同一个核心，不各自复制项目或校准逻辑；实时窗口只读取已经验证过的合成结果，编辑器和 Agent 都进入同一修订事务，不直接重写自动绑定基线。

```text
PSD + 可选原图
      │
      ▼
@puppetloom/core
  导入 → 分类 → 自动定位/检查/修正关键点 → 控制笼/网格/权重 → 13 姿态检查 → 自动收缩/降级
      │
      ├── puppetloom.json（自动绑定基线）
      ├── model（参数 / 关键形态 / 变形器 / 表情 / 物理 / 行为）
      ├── calibration/current.json（当前稀疏覆盖与 authoring 模型）
      ├── calibration/sessions/*.json（修订与用户判断）
      └── textures
                         │
                         ├── CLI describe / author / render / calibrate / compare / export
                         ├── Electron 校准编辑器与 authoring 检查面板
                         ▼
               @puppetloom/renderer
          WebGL2 + 统一姿态场 + 确定性动作
                         │
                         ▼
             Electron 透明角色窗口
```

## 工作区职责

### `packages/core`

`core` 是唯一创建真源。它负责：

- 用 `ag-psd` 读取原始像素数据，遍历嵌套图层并继承分组可见性和透明度；
- 把 8、16 和 32 位像素转换到运行纹理，应用可读取的位图或矢量蒙版；
- 根据名称与透明区域分类，拆分确实跨越画布中心的成对部位；
- 推导脸部、眼角、嘴角、头骨、脖子、肩部、身体和头发固定区域的关键点，并从前发 Alpha 横截面分别定位呆毛根部与刘海根部；
- 校验控制点的左右顺序、上下顺序、眼睛与嘴部包含关系和头颈连接，修正可以由现有像素约束确定的异常点，并记录每一点的来源与置信度；
- 从每层真实 Alpha 提取独立外轮廓与孔洞，生成带内部采样点的约束三角 ArtMesh；完全不透明矩形图层可保留紧凑规则网格，规则 Warp 控制网与渲染网格分开；
- 检查 13 个姿态并依次收缩动作；仍不安全时从 `semantic` 降为 `grouped`，再降为 `minimal`；
- 写入项目、纹理、构建报告、真实姿态图和可选素材请求；
- 把自动绑定基线与用户/Agent 校准覆盖合成为运行项目，验证校准补丁，原子写入新修订，并保留可恢复的会话历史；
- 迁移 v1/v2/v3 项目、补齐网格拓扑声明并建立标准语义参数；验证一维/二维关键形态、旋转/网格变形器、表情、参数物理和行为组成的无环 authoring 图；
- 把高层 authoring 操作展开为同一校准覆盖，在会话中同时保留操作意图，并为关键形态、表情、物理和行为生成参数驱动的前后证据；
- 为指定修订渲染九个主姿态、九个次级运动、修改前后拼图和像素差异图；
- 把当前有效修订烘焙为新的、经过验证的普通项目目录，不创建私有包或覆盖已有目录；
- 分析 PuppetLoom 到 Cubism 的参数和关键形态覆盖，生成公开的 exp3/motion3/physics3/cdi3 文件，验证 Editor 官方导出的 model3/moc3 运行时目录；
- 通过 Cubism Editor External API 读取参数与对象，在可回滚事务中同步 API 允许写入的参数、关键点、ArtMesh/变形器属性，并把不可写的顶点几何保留为显式阻断项；
- 导出闭眼与闭合、微张、小幅张开三态嘴形的精确参考裁切，验证补充素材的尺寸、透明度和覆盖比例，接入前保留原项目备份。

`core` 另有 `@puppetloom/core/browser` 纯运算入口，只导出类型、数学与变形函数，避免浏览器包连带加载文件系统、PSD 解码和 Sharp。

### `packages/renderer`

`renderer` 只消费已验证项目。它为每层上传纹理和索引缓冲，每帧先求值语义/自定义参数、表情和行为，再应用关键形态、子到父变形器、自动姿态和参数物理；虹膜使用对应眼白纹理的真实 Alpha 裁切。普通、正片叠底、滤色、线性减淡、变暗和变亮使用 WebGL 混合状态。参数驱动的图层顺序、表情透明度和混合模式归一化由 `core/render-contract` 统一定义，离线证据按同一求值链、预乘 Alpha 公式和裁剪蒙版渲染，不再维护近似实现。

`CalmMotionController` 可以接收自主观察目标或系统光标目标。桌面主进程读取 Windows 光标与角色窗口的屏幕坐标，使用项目自动定位出的鼻点/头部中心作为方向原点，再把安全范围内的二维目标送进运动控制器。视线使用更快的目标响应，头部经过二阶阻尼追随；脖子与上半身直接读取同一平滑头部状态，以较小比例同时转向和俯仰，不再经过第二套会造成脱节的慢响应器。纵向目标绕头部横轴改变脸部和头骨表面：鼻口、双眼等靠前位置比脸缘移动更多，头顶、下巴、前发、耳朵和头饰按各自表面深度改变轮廓；脖子上端连接头部，下端连接同时运动的衣领，不额外升降整颗头。关闭鼠标跟随时，控制器恢复带种子的自主观察段落，约十五秒依次完成两个相反方向的左右观察、抬头看和低头看；动作之间会回正，避免一直摇摆。前发、后发、头饰、衣摆、尾巴和普通饰品分别读取头部或身体速度，并使用不同频率与相位的驱动进入各自的多段弹性链。后发比此前提高了链条刚度和风动频率，仍比前发厚重，但不再慢半拍拖行；裙摆保持连续运动，同时略微收小幅度。呆毛平时随头发横摆，明显的纵向弹动另由偶发事件激发；耳朵按事件连续快速抬落三至四次，随后严格回到中立。三态嘴形启用后，每次说话由四至七次有间隔、有强弱变化的短开合组成。它没有每帧无关随机数，因此同一项目、同一种子和同一时间序列得到相同动作，但各部位不会复制同一方向的摆动。测试入口既能关闭所有主运动，只保留持续风动与呆毛、耳朵事件，也能输出完整自主段落，分别检查次级运动和整体表演。

次级运动不是整层平移。每类部件先随所属头部或身体的连接点移动，再围绕自己的局部根部弯曲。前发左右、后发左右、呆毛、头饰、上衣、裙摆、尾巴和饰品分别拥有由根部向自由端传递的三至五段状态；根部先响应，自由端延迟并逐渐放大，回正也沿相同链路传播。头发把头部与身体速度按 `60/40` 混合，头饰更偏向身体连接，上衣、裙摆和尾巴只读取身体结果。前发不再用整个图层包围盒估算一条通用发根：程序逐行分析 Alpha 的宽度、填充率和分叉数，窄形状变成宽而连续的首行作为呆毛根部，宽发片开始分成多束的位置作为刘海根部。呆毛只影响前一根部上方，刘海只影响后一根部下方，两根之间的头皮是刚性保护区；为让这条边界落在网格上，前发至少使用 `12×18` 网格。转头时，中央刘海继续服从头骨表面，脸两侧发束则按同一高度读取左右脸缘的实际位移，平滑保持原有间距，然后才叠加发梢惯性，因此不会一侧遮脸、另一侧离脸。合并的头饰图层根据脸部边缘与 Alpha 形状推导左右耳根，为两只耳朵建立独立铰链，钉点邻域保持不动，一次触发让耳尖连续快速抬落三至四次，女仆发箍仍只做轻微整体回弹；前后发使用不同响应；裙子固定腰线，由独立的双频时间线持续左右摆动。尾巴不再修改纵坐标或缩放纹理，而是固定根部、保持各点到根部的距离，通过更快的阻尼转轴沿圆弧上下摆动，并允许很小的分段延迟。不同部位即使合并在一张纹理里也不会获得同样的方向和摆幅。该关系来自对两套本机参考模型的参数、物理链和动作文件的结构分析，具体证据和采用边界见 [Live2D 运动参考结论](LIVE2D_MOTION_REFERENCE.md)。

脖子同时属于头部连接和身体连接，但两种权重沿纵向相反变化：上端完整跟头，下端完整跟衣领。上半身与头部同时起动，但按语义缩小幅度：上衣、手臂和手明显参与，裙摆较轻，腿很小，脚为零。这样头颈不会因时间差断开，也不会把整个人物连脚一起拖走。

语义绑定使用由关键点推导的脸部表面、头骨表面和三角控制笼。脸型、眼角、双眼、鼻口、脸颊、下颌与脖子组成连续脸部网；头顶、额头、两侧头骨和脸缘组成头骨网。每个网格顶点先在对应表面得到转头目标，再由三角重心插值传给实际图层网格；控制笼外的像素按距离和点位置信度平滑衰减。脸、五官使用脸部组，头发、耳朵和头饰使用头骨组，两组共享同一个头部根节点和 yaw/pitch，而不是各层独立平移。构建报告会列出控制点、自动修正和实际受作用的 PSD 图层。具体模型和来源边界见 [统一姿态模型](COHERENT_POSE_MODEL.md)。

### `apps/cli`

CLI 是 Agent 和自动化入口。命令只调用 `core`：`describe` 读取稳定的控制点、图层和网格 ID；`author inspect/apply` 读取并事务修改参数图；`render` 生成视觉证据；`calibrate` 保存经过安全检查的稀疏修改；`compare/history/restore/evidence` 负责审计与用户确认；`export` 发布验证后的目录式副本；`cubism` 分析兼容范围、连接 Editor、生成侧车并最终验证官方运行时目录；`edit/play` 启动同一 Electron 应用。错误在最外层统一映射为退出码，JSON 错误写到标准错误。

### `apps/desktop`

Electron 主进程只编排应用和窗口生命周期。创建器与编辑器由同一个显式 `frame: false` 的控制窗口承载；主进程拥有最小化、最大化、还原、关闭和实际窗口状态，预加载层只暴露受限的窗口外壳 IPC，React 的 `WindowTitleBar` 负责呈现和发起动作。关闭动作仍进入 BrowserWindow 的正常 `close` 流程，因此编辑器原有的草稿刷新拦截不会被绕过。`project-ipc.ts` 封装文件对话框、项目发布、最近项目和受目录边界约束的资源读取；`calibration-ipc.ts` 封装编辑器 IPC、草稿串行化和证据读取，实际持久事务只由 `core` 执行。预加载脚本只暴露明确 IPC，React 界面不含直接文件系统权限；草稿自动保存和关窗刷新集中在 `useEditorDraftPersistence`，`EditorPresentation` 把图层树、画布覆盖层、authoring 检查、证据预览、属性与历史面板保持为无持久化职责的展示组件，`EditorWorkspace` 只编排编辑状态和操作。编辑器让用户在真实 WebGL 合成上用指针或键盘调整语义控制点、身体锚点、图层轴心、次级锚点与网格顶点，并只读核对 AI 写入的参数、绑定、变形器、表情、物理和行为。渲染层通过 `updateProject` 即时预览，不重复上传纹理。角色窗口以 20 Hz 读取光标目标，实时动作在 60 Hz 内部阻尼补间；暂停时播放时钟扣除停顿时长，恢复不会跳相位。

`puppetloom.json` 始终保留可复现的自动绑定基线。创建器先在同级 pending 目录生成、强验证，再以目录移动作为发布点；目标原先为空时也先移动到操作归档，不删除。`calibration/current.json` 只记录偏离基线的内容和唯一历史头；`loadProject` 返回基线与覆盖合成结果。稀疏点位、权重和运行参数之外，校准层也允许保存完整替换网格，用于把旧项目从矩形网格非破坏式升级为 Alpha ArtMesh；替换仍经过同一 schema、安全姿态和视觉证据边界。校准先写 pending 操作、生成并校验证据、写不可达会话，最后原子切换当前头。这样恢复自动绑定不需要猜测旧数值，并发和中断也不会形成两个“当前版本”。用户在界面中的一次保存与 Agent 通过 CLI 的一次修改进入同一修订链，接受或拒绝状态记录在会话中，但单个角色的接受记录不会自动变成所有角色的通用规则。

## 安全结果优先级

每次创建先按 PSD 语义完整度选择初始档位，再对预设姿态验证。动作缩放序列为 `1、0.85、0.7、0.55、0.4、0.25`。一个档位在最小范围仍出现网格翻转、严重拉伸或部件分离才会降级。`minimal` 不做脸部或肢体局部变形，只保留轻微整体呼吸、重心和倾斜，因此不依赖特定角色结构。

嘴部图层会随头部整体运动。运行姿态只有一个连续的 `mouthOpen` 参数，在自然闭口、微张和小幅张开三层之间交叉淡化；自然闭口素材通过后，PSD 原嘴层只作为零透明度回退保留。闭合、微张和张开三态全部通过验证后，运行时才启用偶发的缓慢开合事件；每次事件包含张开、短暂停留和回到闭合的完整过程，事件间隔由种子确定，不形成连续无声说话。闭眼素材接入后，原眼睛在短暂收拢的同时淡出，闭眼线淡入；缺少闭眼图层只会关闭眨眼并生成请求，不影响项目成功。

## 仍需真实素材验证的边界

程序化 PSD 能证明格式、分类、绑定、降级、渲染和产品链正确，但不能证明任意插画的分层质量。真实角色接入阶段仍要确认：PSD 重组与原图一致、脸部关键层完整、头发固定区合理，以及动作在具体线稿上没有视觉穿帮。这是唯一保留给新角色原图和对应 PSD 的验收阶段。
