# 架构说明

PuppetLoom 把“读懂 PSD、生成安全项目”和“实时绘制项目”分开。桌面应用与 CLI 都调用同一个核心，不各自复制创建逻辑；实时窗口只读取已经验证过的项目，不承担绑定编辑职责。

```text
PSD + 可选原图
      │
      ▼
@puppetloom/core
  导入 → 分类 → 自动定位/检查/修正关键点 → 控制笼/网格/权重 → 13 姿态检查 → 自动收缩/降级
      │
      ├── 普通项目目录 ──→ CLI verify / enhance
      │
      └── puppetloom.json + textures
                         │
                         ▼
               @puppetloom/renderer
          WebGL2 + 统一姿态场 + 确定性动作
                         │
                         ▼
             Electron 透明角色窗口
```

## 工作区职责

### `packages/core`

`core` 是唯一创建真源。它负责：

- 用 `ag-psd` 读取原始像素数据，遍历嵌套图层并继承分组可见性和透明度；
- 把 8、16 和 32 位像素转换到运行纹理，应用可读取的位图或矢量蒙版；
- 根据名称与透明区域分类，拆分确实跨越画布中心的成对部位；
- 推导脸部、眼角、嘴角、头骨、脖子、肩部、身体和头发固定区域的关键点；
- 校验控制点的左右顺序、上下顺序、眼睛与嘴部包含关系和头颈连接，修正可以由现有像素约束确定的异常点，并记录每一点的来源与置信度；
- 生成自适应规则网格、作用权重、视线裁切关系和动作上限；
- 检查 13 个姿态并依次收缩动作；仍不安全时从 `semantic` 降为 `grouped`，再降为 `minimal`；
- 写入项目、纹理、构建报告、真实姿态图和可选素材请求；
- 导出闭眼与闭合、微张、小幅张开三态嘴形的精确参考裁切，验证补充素材的尺寸、透明度和覆盖比例，接入前保留原项目备份。

`core` 另有 `@puppetloom/core/browser` 纯运算入口，只导出类型、数学与变形函数，避免浏览器包连带加载文件系统、PSD 解码和 Sharp。

### `packages/renderer`

`renderer` 只消费已验证项目。它为每层上传纹理和索引缓冲，每帧按统一变形函数更新顶点；虹膜使用对应眼白的安全区域裁切。普通、正片叠底、滤色、线性减淡、变暗和变亮使用 WebGL 混合状态；无法直接由固定混合管线复现的模式保留在项目中，并以普通 Alpha 合成安全显示。

`CalmMotionController` 可以接收自主观察目标或系统光标目标。桌面主进程读取 Windows 光标与角色窗口的屏幕坐标，使用项目自动定位出的鼻点/头部中心作为方向原点，再把安全范围内的二维目标送进运动控制器。视线使用更快的目标响应，头部经过二阶阻尼追随，身体读取已经平滑的头部状态并延迟跟随，同时从头部转向和俯仰获得小幅上半身旋转。纵向目标绕头部横轴改变脸部和头骨表面：鼻口、双眼等靠前位置比脸缘移动更多，头顶、下巴、前发、耳朵和头饰按各自表面深度改变轮廓，脖子只连续连接头和衣领，不额外升降整颗头。关闭鼠标跟随时，控制器恢复带种子的自主观察事件。前发、后发、头饰、衣摆、尾巴和普通饰品分别读取头部或身体速度，并使用不同频率与相位的缓慢驱动进入各自的多段弹性链。呆毛平时随头发横摆，明显的纵向弹动另由偶发事件激发；耳朵按事件连续快速抬落三至四次，随后严格回到中立。它没有每帧无关随机数，因此同一项目、同一种子和同一时间序列得到相同动作，但各部位不会复制同一方向的摆动。测试入口还能关闭所有主运动，只保留持续风动与仍会按时间触发的呆毛、耳朵事件，防止把头部位移误当成次级运动。

次级运动不是整层平移。每类部件先随所属头部或身体的连接点移动，再围绕自己的局部根部弯曲。前发左右、后发左右、呆毛、头饰、上衣、裙摆、尾巴和饰品分别拥有由根部向自由端传递的三至五段状态；根部先响应，自由端延迟并逐渐放大，回正也沿相同链路传播。头发把头部与身体速度按 `60/40` 混合，头饰更偏向身体连接，上衣、裙摆和尾巴只读取身体结果。前发图层的中央上部作为呆毛、下部作为刘海分别加权；合并的头饰图层根据脸部边缘与 Alpha 形状推导左右耳根，为两只耳朵建立独立铰链，钉点邻域保持不动，一次触发让耳尖连续快速抬落三至四次，女仆发箍仍只做轻微整体回弹；前后发使用不同响应；上衣固定肩部、裙子固定腰线、尾巴固定根部，越靠近自由端位移越大。不同部位即使合并在一张纹理里也不会获得同样的方向和摆幅。该关系来自对两套本机参考模型的参数、物理链和动作文件的结构分析，具体证据和采用边界见 [Live2D 运动参考结论](LIVE2D_MOTION_REFERENCE.md)。

脖子同时属于头部连接和身体连接，但两种权重沿纵向相反变化：上端完整跟头，下端完整跟衣领。身体跟随也按语义衰减，上衣、手臂和手明显参与，裙摆较轻，腿很小，脚为零。这样头部可以先转而不与身体断开，上半身随后转向时也不会把整个人物连脚一起拖走。

语义绑定使用由关键点推导的脸部表面、头骨表面和三角控制笼。脸型、眼角、双眼、鼻口、脸颊、下颌与脖子组成连续脸部网；头顶、额头、两侧头骨和脸缘组成头骨网。每个网格顶点先在对应表面得到转头目标，再由三角重心插值传给实际图层网格；控制笼外的像素按距离和点位置信度平滑衰减。脸、五官使用脸部组，头发、耳朵和头饰使用头骨组，两组共享同一个头部根节点和 yaw/pitch，而不是各层独立平移。构建报告会列出控制点、自动修正和实际受作用的 PSD 图层。具体模型和来源边界见 [统一姿态模型](COHERENT_POSE_MODEL.md)。

### `apps/cli`

CLI 是 Agent 和自动化入口。命令只调用 `core`，`play` 启动同一 Electron 透明窗口。错误在最外层统一映射为退出码，JSON 错误写到标准错误。

### `apps/desktop`

Electron 主进程拥有文件对话框、项目创建、纹理读取、系统光标坐标和角色窗口控制权；预加载脚本只暴露明确 IPC。React 创建界面不含文件系统权限。角色窗口以 20 Hz 读取光标目标，实时动作在 60 Hz 内部阻尼补间，避免高频 IPC 影响渲染；该读取不依赖窗口接收鼠标事件，因此穿透模式仍然有效。角色窗口使用相同页面的 viewer 模式，WebGL 画布保持透明，隐藏控制区在鼠标悬停时出现。

## 安全结果优先级

每次创建先按 PSD 语义完整度选择初始档位，再对预设姿态验证。动作缩放序列为 `1、0.85、0.7、0.55、0.4、0.25`。一个档位在最小范围仍出现网格翻转、严重拉伸或部件分离才会降级。`minimal` 不做脸部或肢体局部变形，只保留轻微整体呼吸、重心和倾斜，因此不依赖特定角色结构。

嘴部图层会随头部整体运动。运行姿态只有一个连续的 `mouthOpen` 参数，在自然闭口、微张和小幅张开三层之间交叉淡化；自然闭口素材通过后，PSD 原嘴层只作为零透明度回退保留。闭合、微张和张开三态全部通过验证后，运行时才启用偶发的缓慢开合事件；每次事件包含张开、短暂停留和回到闭合的完整过程，事件间隔由种子确定，不形成连续无声说话。闭眼素材接入后，原眼睛在短暂收拢的同时淡出，闭眼线淡入；缺少闭眼图层只会关闭眨眼并生成请求，不影响项目成功。

## 仍需真实素材验证的边界

程序化 PSD 能证明格式、分类、绑定、降级、渲染和产品链正确，但不能证明任意插画的分层质量。真实角色接入阶段仍要确认：PSD 重组与原图一致、脸部关键层完整、头发固定区合理，以及动作在具体线稿上没有视觉穿帮。这是唯一保留给新角色原图和对应 PSD 的验收阶段。
