# 猫娘变形问题复核与修正

本次检查针对任务 `01a076f3-f198-7431-bcae-eeab65ec3f12` 中的角色制作过程，以及用户指出的脸部和闭眼变形。结果保存在 `workspace/analysis/live2d-capability-20260907/candidate`。第 17 版交付后被用户指出仍有眼角侧壁和闭眼弧线问题；后续已修到第 19 版，见下方返修记录。这些都是研究候选项目的版本号。

## 原因与处理

原来的问题不能单独归因于参考项目。此前实现把参考项目的默认头脸运动移植到当前角色，又用固定转角、近远眼比例和下半脸伸缩比判断制作是否合格。技术检查能够证明网格没有翻折，却不能证明这张脸仍然符合原画。闭眼使用稀疏网格和自动生成的目标，出现了明显折角；执行结果又被标为完成，让技术成功掩盖了造型失败。

通用代码现在保留角色已设定的头脸幅度、透视和修形强度，允许显式设置小角度或零强度。近远眼和脸部伸缩数据放入 `measurements` 供观察，不再把统一比例当成所有角色必须满足的造型标准。仍保留中立姿态、其他图层、网格和关联关系的技术检查。

`agent apply` 成功执行后返回 `awaiting-visual-review` 和 `visualReview: unreviewed`；分部报告另行记录 `executionStatus: succeeded`。外部 Agent 仍须看实际输出并修复具体缺陷。更改状态名称不会自动赋予软件识图能力，也不会代替视觉判断。用户接受状态继续使用已有校准 session 的证据接口记录。

## 当前角色的眼睛

本次以候选第 14 版为基线，经公开 `calibrate` 和 `author apply` 接口保存第 15、16、17 版。左右睫毛分别补充网格，并按原图中各自的眼角位置、倾斜方向和笔触制作闭合关键形。原睫毛与眼白纹理沿连续关键形变形，虹膜随眼白遮罩闭合；没有读取或显示替换用闭眼图片。原项目已有的闭眼图层仍留在项目中，不参与本次几何闭合。

这些闭合曲线属于当前角色的数据，未加入通用默认算法。自动闭眼生成器仍是起稿工具；其他角色也需要根据自身原图修形和复核。已制作的关键形、既有表情及用户选择的闭眼模式受保留，重复制作不会静默套回默认值。

这次眼部修正保留候选第 14 版的脸部运动；8 秒、192 帧的同参数前后对照中，脸部点位最大差异为 0。它证明眼睛改善没有依赖再次改脸，不代表已经重新完成整个人物的脸部制作。睫毛换网格后，中立帧有少量边缘采样差异，不宣称像素完全一致。
