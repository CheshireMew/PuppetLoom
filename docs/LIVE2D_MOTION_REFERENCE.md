# Live2D 运动参考结论

PuppetLoom 不读取或输出 Cubism 模型。这次仅在本机分析用户提供的两套运行模型，用它们回答一个具体问题：成熟角色为什么不会让所有图层以同一方向、同一速度一起摆动。参考文件没有复制进仓库，纹理、网格、动作数据和模型参数也不会成为 PuppetLoom 项目的一部分。

## 可验证的结构

官方 Hiyori 运行模型包含 70 个公开参数、11 组物理链、34 个物理输入、35 个输出和 58 个物理节点。它把前发、后发、呆毛、发饰、胸前饰品、裙摆和身体分别处理。头发类输入通常由头部与身体按 `60/40` 混合，发饰更偏向身体，裙摆和胸前饰品只读取身体。长发和前发左右两侧各自使用七段输出，证明发梢不是围绕一个中心点做整层旋转。

用户提供的 miku 运行模型包含 141 个公开参数、40 组物理链、91 个输入、83 个输出和 120 个物理节点。除前发、侧发、后发分别处理外，它还把肩膀、上下身、眼皮、瞳孔和高光联动拆开；较长部件使用多级节点，不同方向可以使用相反映射。它的使用说明禁止二改和二传，因此 PuppetLoom 只采用这些通用结构事实，不复制具体数值、素材或模型文件。

## PuppetLoom 的对应实现

- 视线、头部、身体按先后顺序追随同一个目标；身体同时读取头部横向转动与纵向俯仰。
- 前发左右、后发左右分别使用独立的多段链。两侧有轻微不同的响应和低频驱动，前发与后发的速度、摆幅和相位也不同。
- 每条链从固定根部向自由端传递。根部先响应，发梢、裙摆或尾端延迟并放大；停止驱动后再逐段回正。
- 头发混合头部与身体速度，头饰以头部连接为主但更稳定；上衣、裙摆和尾巴读取与头部同步起动、幅度更小的身体运动，再各自产生软体滞后。
- 呆毛的常态风动与偶发强弹分开；耳朵的静止状态与连续三至四次快速抬落事件分开。
- 旧版单值状态继续保留为兼容输出，实际网格优先读取多段状态，因此测试和诊断脚本仍能比较总体峰值。

这些规则仍受 PuppetLoom 的固定点、语义网格和安全范围约束。参考模型只能提供运动关系，不能替代对当前 PSD 的关键点定位，也不能凭空补出原图没有分开的头发或衣服。
