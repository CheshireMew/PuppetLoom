# 统一姿态模型

第三个演示项目没有公开源码，因此 PuppetLoom 没有复刻其内部代码。能从原视频界面确认的是：它按导入、拆分、绑骨、姿态、眨眼、口型、呼吸、预览、导出组织流程；姿态阶段提供头脸、身体、前发和后发模板，使用语义点与连线，支持单项校准、自动巡检、穿帮修正和作用图层确认；预览阶段另有幅度、响应、稳定性和性能诊断。基于这些可见事实，PuppetLoom 独立实现了下面这套适合无人工绑定目标的模型。详细取舍见 [视频参考结论](VIDEO_REFERENCE_FINDINGS.md)。

## 一次姿态，分层响应

运行时只生成一组连续的头部 yaw、pitch 和 roll。程序先从图层 Alpha 自动定位 23 个语义点，检查左右/上下顺序、眼口包含关系与头颈连接，并只修正能由现有像素约束确定的异常。脸部表面和头骨表面负责给这些点生成转头目标；额头、鼻根、鼻尖、上唇、下唇和下巴组成的可编辑深度曲线补充脸部纵向 Z 形状，脸部与头骨三角控制网再把点位变化连续传给真实网格。该曲线只参与非中立投影，所有参数归零时仍严格返回原网格。控制网内部使用重心插值，外部按距离与置信度平滑衰减。这样眼角、脸颊、下颌和前发边缘会参与同一次形变，不再只是把眼睛和头发作为独立贴片平移。转向时，远侧眼通过收窄和位移表达透视，眼睛与眉毛始终保持完全不透明；超过可调阈值后，只有耳朵和侧发等外围部件会平滑降低可见度。近侧侧发可以进入脸前，远侧侧发留在脸后，避免固定 PSD 顺序承担全部遮挡。

左右眼不是等宽平移。转头时靠近观察者的一侧眼白、睫毛和眼角会略微变宽，远侧略微变窄；同一只眼的眼白、虹膜、睫毛和闭眼素材共用由眼白推导的眼眶中心，避免各层绕自己的包围盒中心缩放后在眼角露出白边。虹膜仍由对应眼白的 Alpha 区域裁切。视线先到目标，但随着头部完成转向会在眼眶内部分回中，避免眼球已经顶到一侧而脸仍像正面。脸层还会让远侧脸颊向内收、下巴随转向偏移；图层语义继续决定相对深度和局部参与比例，例如鼻子略靠前、后发略靠后、发梢比发根更自由。

头部目标先经过二阶阻尼响应，避免观察动作瞬间开始或停止。视线会比头部提前；脖子和上半身直接读取已经平滑的头部状态，以较小比例在同一时刻进入转向和俯仰，不再额外延迟。上下观察使用脸部和头骨表面的横轴旋转：表面深度决定各点的纵向位移，靠前五官与侧缘轮廓不会等量平移，因此形成抬脸和低头而不是伸头、缩头；颈部上端连接头部姿态，下端连接同时运动的衣领。头骨、前发根、后发根、耳朵和头饰共享同一球面根位移，只有自由端保留各自弹性。前发、侧发和后发会从 Alpha 下缘识别多条房束，每条房束有独立的根梢、网格归属、释放曲线和三至五段弹簧状态。头皮附着遮罩使房束根部跟随同一个头骨姿态，物理释放遮罩让发梢逐步获得延迟与回弹；根部不会再被旧的左右弹簧重复施加一次。识别不到可靠房束的旧项目仍走原有左右链。前发图层内部继续由 Alpha 形状分出呆毛根、不可摆动的头皮和刘海根，脸侧前发按同一高度的脸缘位移校正横向间距。它们仍由同一条确定性时间线驱动，但每条房束使用由稳定 ID 推导的相位，不会逐帧加入随机数。头饰、合并耳朵、裙摆和尾巴继续使用各自的连接点和运动约束；固定根部保持不动，自由端才获得较大位移。关闭头部与身体主运动后，持续风动和按时间触发的局部事件仍然存在。

颈部不是整层平移。靠近下巴的上端完整继承头部连接位移，靠近衣领的下端逐渐切换为同步缩幅后的上半身位移；两端同时开始运动，中间只负责连续过渡，不再把时间延迟误写成脖子拉伸。上衣、手臂和手的跟随幅度最大，裙摆次之，腿只保留很小的传递，脚保持落点。自主时间线也会交替安排横向观察、轻微低头和抬头，而不是把所有变化混在同一个斜向摆动中。

```text
带种子的观察目标
  ├─→ 视线提前
  └─→ 阻尼头部姿态 ─→ 共同头部根节点
                   ├─→ 脸部表面 ─→ 脸型 / 远近眼 / 眉毛 / 鼻口
                   ├─→ 头骨表面 ─→ 头发 / 耳朵 / 头饰
                   ├─→ 同步缩幅 ─→ 脖子与上身结构联动
                   └─→ 头部与身体速度 + 分相低频驱动
                                      └─→ 呆毛 / 前后发 / 头饰 / 耳朵 / 衣摆 / 尾巴 / 饰品惯性
```

## 自动生成与安全边界

两套表面的中心、半径和控制笼都来自 PSD 的语义图层与透明像素，不依赖当前角色的手工参数。中立状态严格返回原网格，因此不会改变 PSD 重组结果。创建阶段会先检查并在可确定范围内修正关键点，然后使用 13 个姿态检查网格翻转、严重拉伸、眼睛越界、脸发分离、颈部断开和画布越界；不安全时缩小动作或降为分组、最保守绑定。每个控制点的来源、置信度、修正记录和作用图层都会写入报告，供 Agent 自动复核。

这套姿势实现采用了演示项目表现出的“共同姿态加分组响应”思路，但不包含其骨骼编辑器或任何未公开实现。PuppetLoom 后续独立接入了官方 MediaPipe Tasks Vision 作为一种可选实时输入；它只产生与鼠标、麦克风和外部 CLI 相同的运行时控制值，不改变姿势几何的确定性实现。
